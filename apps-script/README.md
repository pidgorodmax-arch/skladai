# Apps Script: Google Таблиця → API для SkladAI

`Code.gs` перетворює Google Таблицю клієнта на маленький API (Web App):

- **GET** — віддає всі вкладки одним JSON у форматі застосунку;
- **POST** — застосовує одну дію (нова партія, переміщення, списання, статус
  замовлення) і пише рядок у `Registro`.

Структура таблиці — [`docs/sheets.md`](../docs/sheets.md). Спершу створи
таблицю за ним, потім розгортай скрипт.

> **Репозиторій публічний.** Адресу Web App і токен не пиши в код, у
> коміти, в issues чи PR. Вони живуть лише у властивостях скрипта й у
> налаштуваннях застосунку на телефоні (завдання 2.4).

## Розгортання (≈10 хвилин, один раз)

1. **Часовий пояс таблиці.** У таблиці: **File → Impostazioni → Fuso
   orario → (GMT+01:00) Roma** → Salva.
2. **Відкрий редактор скрипта:** **Estensioni → Apps Script**. Відкриється
   новий проєкт, прив'язаний саме до цієї таблиці.
3. **Код.** У файлі `Codice.gs` видали все й встав вміст
   [`apps-script/Code.gs`](Code.gs). Натисни 💾 (Salva progetto).
4. **Маніфест.** Ліворуч ⚙️ **Impostazioni progetto** → увімкни
   «Mostra il file manifest "appsscript.json" nell'editor». Повернись у
   редактор (`<>`), відкрий `appsscript.json` і заміни вміст на
   [`apps-script/appsscript.json`](appsscript.json). Там пояс `Europe/Rome`
   і налаштування Web App. Збережи.
5. **Токен (пароль для API).** ⚙️ **Impostazioni progetto → Proprietà
   script → Aggiungi proprietà script**: назва `TOKEN`, значення — довгий
   випадковий рядок (≥ 32 символи, наприклад з менеджера паролів або
   `openssl rand -hex 24`). Salva. Без нього скрипт відповідає
   `TOKEN non configurato…`.
6. **Опублікуй як Web App:** угорі **Esegui il deployment → Nuovo
   deployment** → ⚙️ біля «Seleziona tipo» → **App web**:
   - *Descrizione*: `SkladAI v1`
   - *Esegui come*: **Io (твоя пошта)** — скрипт пише в таблицю від твого імені
   - *Chi ha accesso*: **Chiunque** (застосунок на телефоні без входу в
     Google; захист — токен)

   → **Esegui il deployment**.
7. **Дозволи.** Google попросить доступ до таблиць: **Autorizza accesso**
   → обери свій акаунт. Якщо з'явиться «Google non ha verificato
   quest'app» — це нормально для власного скрипта: **Avanzate → Vai a … (non
   sicuro)** → **Consenti**.
8. **Скопіюй URL Web App** (закінчується на `/exec`). Він знадобиться для
   перевірки нижче й у налаштуваннях застосунку.
9. **Підключи застосунок.** На телефоні відкрий SkladAI → внизу
   **Impostazioni** → встав адресу й токен → **Verifica e collega**. Якщо
   таблиця відповідає, застосунок перемкнеться на неї (унизу: «dati dalla
   tabella Google»). Зміни, зроблені прямо в таблиці, з'являються після
   **Aggiorna dati**.

### Якщо токен «засвітився»

Токен у GET-запиті видно в історії браузера й терміналу. Якщо він міг
потрапити до сторонніх — зміни значення `TOKEN` у **Proprietà script**
(новий deployment не потрібен, URL лишається той самий) і внеси новий токен
у застосунок.

### Оновлення скрипта

Після зміни коду: **Esegui il deployment → Gestisci deployment** → ✏️ →
*Versione*: **Nuova versione** → **Esegui il deployment**. URL лишається
той самий. (Якщо створити *новий* deployment — URL зміниться.)

**Оновлення до коробок (2b.1a).** Якщо таблиця створена раніше (без
вкладки `Colli`), просто встав новий `Code.gs` і зроби нову версію, як
вище. Таблиця й далі читається; під час першого запису з телефона скрипт
сам створить `Colli` і перенесе туди кількості з `Lotti`
(див. `docs/sheets.md`, вкладка `Colli`).

## Ручна перевірка з curl

Підстав свої значення (у терміналі; на Windows — Git Bash):

```bash
URL='https://script.google.com/macros/s/…/exec'
TOKEN='твій-токен'
```

**1. Прочитати всю таблицю:**

```bash
curl -sL "$URL?token=$TOKEN"
```

Очікувано: `{"ok":true,"state":{"version":2,"products":[…],"zones":[…],…}}`.
`-L` обов'язковий: Google спершу відповідає переадресацією.

**2. Записати нову партію** (заміни `mozzarella` і `C2-1` на `id` зі своїх
вкладок `Prodotti` і `Posizioni`):

```bash
curl -sL -H 'Content-Type: text/plain' \
  -d '{"token":"'"$TOKEN"'","action":{"type":"register","productId":"mozzarella","qty":10,"locationId":"C2-1"}}' \
  "$URL"
```

Очікувано: `{"ok":true}`; у вкладці `Lotti` — новий рядок (`codice` = `L-ДДММ-MZ`; без `lotId` у запиті `id` = код), у `Colli` — його коробка `<id>-1`, у
`Registro` — запис «Prodotto lotto …» з часом за Римом.

**3. Помилки** повертаються як `{"ok":false,"error":"…"}` (італійською), а
таблиця не змінюється:

```bash
curl -sL "$URL?token=sbagliato"
# {"ok":false,"error":"Token non valido"}
```

## Дії (тіло POST)

Тіло — JSON `{"token": "…", "action": {…}}`. Дії ті самі, що в застосунку
(`src/data/reducer.ts`). Застосунок додає до кожної дії два службові поля:

- `at` — коли дію зробили на телефоні (`РРРР-ММ-ДДTгг:хх`, Рим). Дія з
  офлайн-черги, відправлена вранці, лишається в `Registro` і в даті партії
  вечірньою. Без `at` береться поточний час.
- `id` — унікальний номер дії. Якщо телефон не отримав відповідь і надіслав
  ту саму дію ще раз, скрипт її пропустить. Пам'ять — CacheService Google:
  до 6 годин, але Google може очистити її раніше. Для звичайного випадку
  (відповідь загубилась, телефон одразу повторив) цього досить.

`at` з майбутнього (годинник телефона поспішає більше ніж на 10 хв)
скрипт не приймає й пише в журнал час отримання.

Помилка містить `code`: `auth` (токен), `config` (таблиця не за
`docs/sheets.md`), `rejected` (дію не можна виконати — застосунок прибирає її
з черги) або `error` (інше — застосунок повторить пізніше).

Таблиця дій:

| `type` | Поля | Що робить у таблиці |
|---|---|---|
| `register` | `productId`, `qty`, `locationId`, `milkLitres?`, `lotId?`, `code?` | Новий рядок у `Lotti` і коробка `<id>-1` у `Colli`. `lotId` — внутрішній ID, створений телефоном (партію з таким ID вдруге не створює). `code` — код, який бачила людина; якщо його вже зайняла інша партія — наступний вільний (`…MZ2`). Дата за Римом, термін = дата + `giorni_scadenza` |
| `move` | `lotId`, `locationId`, `code?`, `from?` | Міняє `posizione` в усіх коробках (`Colli`) партії з **ID** `lotId`, з `from` — лише на цьому стелажі (`code` — лише для повідомлень) |
| `ship` | `lotId`, `qty`, `code?`, `from?` | Бере `qty` з коробок партії з **ID** `lotId` по черзі (з `from` — лише з коробок на цьому стелажі); порожня коробка зникає, партія без коробок — теж |
| `placeBox` | `fromBoxId`, `qty`, `locationId`, `boxId?` | Нова коробка: відділяє `qty` від коробки `fromBoxId` (не більше, ніж у ній) і ставить на `locationId`. `boxId` — код етикетки (дає телефон; без нього — `<партія>-2`, `-3`…). Повтор з тим самим `boxId` нічого не робить |
| `moveBox` | `boxId`, `locationId` | Міняє `posizione` однієї коробки |
| `pick` | `orderId`, `boxId`, `qty` | Збирання: зменшує коробку (не більше, ніж у ній; продукт має бути в замовленні; більше, ніж замовлено, — можна, бо вага упаковок «плаває»), дописує рядок у `Prelievi` з `modo` = `scansionato`; `nuovo` → `in_preparazione` |
| `uscita` | `dest` (`ordine` / `spaccio` / `scarto`), `qty`, `boxId?` або `productId?` | Uscita rapida: з коробки `boxId` (не більше, ніж у ній) або за продуктом — за FEFO з кількох коробок (не більше, ніж є). Дописує рядки в `Uscite` (створює вкладку, якщо її немає) і в `Registro`. Замовлень не створює |
| `orderStatus` | `orderId`, `status` (`nuovo` / `in_preparazione` / `spedito`) | Міняє `stato` в усіх рядках замовлення; `spedito` добирає незібране з коробок за FEFO (рядки `Prelievi` з `modo` = `automatico`) і остаточний |

Кожна дія, крім зміни статусу без відвантаження, дописує рядок у
`Registro`. Одночасні записи з кількох телефонів виконуються по черзі
(`LockService`).

## Як перевіряється без Google

`src/data/appsScript.test.ts` запускає `Code.gs` на фальшивій таблиці (у
пам'яті) і проганяє ті самі дії через reducer застосунку і через скрипт:
результат має збігатися крок за кроком. Там же перевірено, що колонки в
скрипті збігаються з `docs/sheets.md`. Тож якщо змінити правило в одному
місці й забути в іншому — `npm test` упаде.
