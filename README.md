# SkladAI — прототип

**Демо:** https://pidgorodmax-arch.github.io/skladai/

Одна система для малого виробника (сироварня, латтерія): склад і партії,
витримка сирів, замовлення, план виробництва, 3D-карта цеху, екран для
телефона та ранковий брифінг. Усі екрани працюють з **одними даними**:
партія, записана з телефона, одразу з'являється на 3D-карті, у плані
виробництва й у брифінгу.

Інтерфейс італійською (для клієнтів), код і коментарі українською (для нас).

## Екрани

| Маршрут | Що це |
|---|---|
| `#/` | **Cruscotto** — показники, «що виробити», брифінг, терміни, доставки, журнал HACCP |
| `#/magazzino` | **Magazzino 3D** — цех у 3D (Three.js): стелажі з формами Montasio, камери, котли, рампа. Режими кольору: заповненість / вік форм / терміни. Фільтр за продуктом, переміщення і списання партій |
| `#/ordini` | **Ordini** — статуси замовлень; «Spedito» сам списує склад (FEFO) |
| `#/registra` | **Registra** — екран для телефона в цеху: нова партія за 20 секунд, код лоту, термін і вихід рахуються самі |

## Запуск локально

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # збірка в dist/
```

## Публікація (посилання для телефона і клієнтів)

У репозиторії: **Settings → Pages → Source: GitHub Actions**. Після кожного
push у `main` workflow `deploy.yml` збирає й публікує застосунок за адресою
`https://<ваш-логін>.github.io/skladai/`. На телефоні: «Поділитися → На
екран Додому» — з'явиться іконка, як у звичайного застосунку.

## Як влаштовано

```
src/
  data/
    types.ts      — модель: продукти, зони, місця, партії, замовлення, журнал
    seed.ts       — демо-дані (дати відносно сьогодні)
    store.tsx     — ЄДИНЕ сховище стану: усі зміни йдуть через dispatch(...)
    source.ts     — DataSource: load() на старті, apply(action) на кожну зміну;
                    DemoSource — localStorage (далі SheetsSource — Google Sheets)
    reducer.ts    — дії і як вони змінюють стан (register, ship, move, orderStatus)
    persist.ts    — збереження в localStorage, резервна копія нечитабельних даних
    migrate.ts    — міграції: старі збережені дані → поточна версія
    useStore.ts   — доступ до стану й «сьогодні» з екранів
    useToday.ts   — єдине місце, що дивиться на годинник: «сьогодні» для UI
    time.ts       — дата й час за Римом (Europe/Rome), незалежно від поясу пристрою
    selectors.ts  — розрахунки: заповненість, вік, терміни, план виробництва
                    («сьогодні» — параметр, тож рахувати можна на будь-яку дату)
    brief.ts      — ранковий брифінг (поки правила; далі — Claude API)
  pages/
    Dashboard.tsx, Warehouse3D.tsx, Orders.tsx, Register.tsx
```

Дані зараз зберігаються в браузері (localStorage) — кнопка «Ripristina dati
demo» внизу повертає демо.

## Робота з Claude Code

Правила для Claude Code — у `CLAUDE.md`, технічне завдання й етапи — у
`docs/TZ.md` (там же готові промпти, по одному на завдання).

## Наступні кроки

1. **Справжні дані.** Додати `SheetsSource` (той самий інтерфейс, що й `DemoSource` у `source.ts`) для
   Google Sheets (API Sistema Latteria на Apps Script) — екрани не зміняться.
2. **AI-агент.** Невеликий серверний скрипт (як у податковому боті), що
   передає ці ж цифри в Claude API: брифінг текстом, вільні питання,
   повідомлення в Telegram о 6:30.
3. **Реальний план цеху.** Розміри й розташування зон і стелажів — у
   `seed.ts` (`zones`, `locations`, метри).
4. **Кілька клієнтів** → PostgreSQL і вхід за паролем.
