# SkladAI — інструкції для Claude Code

Читай цей файл перед кожним завданням. Повне технічне завдання й етапи — у
`docs/TZ.md`. Поточний етап і чекліст — там само, розділ «Статус».

## Що це за проєкт

SkladAI — система обліку складу й виробництва для малих італійських
харчових виробників (сироварні, латтерії, прошуттифіції у Фріулі).
Власник проєкту — Макс: працює на молочному виробництві, вчиться
програмувати й будувати AI-агентів. Пояснюй рішення простими словами,
коли щось робиш уперше (що, навіщо, де в коді).

## Стек

- Vite + React 19 + TypeScript (strict), React Router (HashRouter)
- Three.js через @react-three/fiber і @react-three/drei — 3D-карта цеху
- Дані зараз: localStorage (демо). Далі: Google Sheets → PostgreSQL
- Публікація: GitHub Pages через `.github/workflows/deploy.yml`
- Без бекенду у фронтенді: ключі API (Claude, Telegram, Google) ніколи не
  потрапляють у код застосунку чи в `VITE_*` змінні

## Команди

```bash
npm install
npm run dev      # локальний сервер
npm run build    # tsc + vite build — МАЄ проходити перед кожним комітом
npm run lint     # oxlint; помилки коректності валять CI
npm test         # vitest
```

## Архітектура — правила, які не можна порушувати

1. **Одне джерело даних.** Будь-яка зміна стану — лише через
   `dispatch(action)`; самі зміни описані в reducer `src/data/reducer.ts`. Сторінки не змінюють дані
   напряму і не тримають власних копій.
2. **Розрахунки — у `src/data/selectors.ts`**, чистими функціями
   (`state, today → число/список`). Без React і без годинника всередині:
   «сьогодні» приходить параметром `today` (у UI — з `useStore()`).
   Ці ж функції використовуватиме AI-агент.
3. **Модель даних — `src/data/types.ts`.** Якщо додаєш поле — онови типи,
   демо-дані в `seed.ts`, збільш `STATE_VERSION` і додай крок у
   `MIGRATIONS` (`src/data/migrate.ts`) з тестом.
4. **Сторінки (`src/pages/`) лише показують дані і викликають dispatch.**
5. **3D-сцена** живе в `Warehouse3D.tsx` і вантажиться ліниво (`lazy`).
   Координати цеху — в метрах (`x`, `z`, `w`, `d`, `h` у `Location`/`Zone`).

## Мова

- Інтерфейс — **італійською** (клієнти італійці). Терміни: lotto,
  scadenza, stagionatura, cella, scaffale, ordine, cotta, resa.
- Коментарі в коді, README, документація, коміти — **українською**.

## Стиль коду

- TypeScript strict, без `any`. Невеликі функції, зрозумілі назви англійською.
- CSS — у `src/index.css` через змінні (`--accent`, `--ink`, …). Без нових
  UI-бібліотек без потреби.
- Доступність: справжні `<button>`, `<label>` до полів, контраст тексту
  ≥ 4.5:1, кнопки не менші за 44 px (застосунок використовують у цеху в
  рукавичках, з телефона).
- Застосунок має працювати на ширині телефона (390 px).

## Як працювати із завданнями

1. Візьми завдання з `docs/TZ.md` (або те, що написав Макс).
2. Створи гілку `feat/<коротка-назва>` або `fix/<...>`.
3. Роби маленькими комітами з повідомленнями українською.
4. Перед комітом: `npm run build`, `npm run lint` і `npm test` без помилок.
5. Перевір у браузері ключовий сценарій завдання (див. критерії прийняття).
6. Відкрий Pull Request: що зроблено, як перевірити, що лишилось. Не зливай
   у `main` сам, якщо Макс не попросив.
7. Онови розділ «Статус» у `docs/TZ.md`.

## Автоматичний режим: /next

  проти цих правил і критеріїв прийняття. Без його APPROVED PR не
  відкривається.
- PR завжди зливає Макс. Наступне завдання починається лише після злиття.

## Чого не робити

- Не комітити секрети, `.env`, ключі. Для ключів — GitHub Secrets.
- Не видаляти демо-режим: без підключених даних застосунок має працювати
  на демо-даних (його показують клієнтам).
- Не міняти модель даних «тихо» — завжди з міграцією та поясненням у PR.
- Не додавати платні сервіси без погодження з Максом.
